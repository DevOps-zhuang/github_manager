## 一、背景
当前系统以 Python CLI 脚本形态为主（批量数据标准化 + 后续邀请辅助），仅适合具备开发背景的人员操作，业务人员门槛高。未来还规划支持 GitHub App 深度集成，但第一阶段核心目标是完成架构重构——将“数据标准化（含 AI 辅助交互式规则确认）”能力 Web 化与服务化，形成上传→ AI 交互修正规则 → 预览 → 确认 → 下载的最小可用闭环，为后续邀请执行、指标、GitHub App、异步任务等扩展奠定基础。

## 二、业务价值
- 降低使用门槛：业务或运营人员可直接通过浏览器进行数据标准化，无需运行 CLI。
- 提升标准化质量：通过多轮交互（AI 辅助规则建议 + 人工微调）减少人工手写转换规则的偏差。
- 加速后续扩展：提前抽象任务、规则、结果的域概念，为引入异步执行、权限多角色、GitHub App 等迭代创造结构空间。
- 降低误操作风险：统一入口与可视化预览降低直接在脚本层面修改导致的隐性错误。

## 三、范围
### 3.1 范围内（Phase 1）
1. 架构重构：提供后端 Web API（Python Flask）与最小 React Web 前端。
2. 上传单个 CSV 文件（大小 ≤ 1MB）并创建标准化任务（生成 task id）。
3. AI 辅助生成初始规则建议（规则内容以“可交互的抽象概念”呈现，不要求固定输出结构在本需求阶段定义）。
4. 多轮对话式交互：用户输入自然语言指令，系统更新“当前规则草稿”并返回最新预览（前 20 行）。
5. 规则确认：用户确认后执行同步标准化，产出最终标准化结果文件与错误行文件。
6. 下载：可下载标准化结果 CSV 与错误行 CSV。
7. 简单认证：最小管理员登录（用户名+密码由初始配置提供，可在登录后修改）。
8. 基础安全：受保护接口需登录态/令牌；错误响应不暴露内部堆栈。
9. 同步执行模式：所有处理在单次请求内完成（确认执行阶段除外的多轮对话仍为同步调用）。
10. 支持并行存在多个任务（不同 task id 相互独立）。
11. 任务与会话需在服务重启后仍可访问（持久化方式不在需求文档中约束实现细节）。
12. 提供健康检查接口（健康状态检测）。

### 3.2 不包含（Phase 1 明确排除）
- GitHub 邀请执行 API（仍线下/CLI 手工）。
- 异步任务队列 / 进度轮询 / 分布式执行。
- 多组织 / 多租户隔离模型。
- GitHub App 安装、Webhook 事件处理、权限绑定。
- 指标统计可视化面板（邀请成功率、活跃度等）。
- 审计日志、操作留痕的结构化归档。
- 精细化权限（仅一个管理员用户）。
- API 版本化策略（统一 /api 前缀即可）。
- 国际化（前端文案默认单语言）。
- 文件增量导入逻辑与差异比对。
- 性能优化（流式处理 / 分块读取 / 内存压缩）。
- 规则高级管理（版本回滚、规则共享库、草稿对比）。
- 任务自动过期与清理策略。
- 规则导出 / 导入（未来可扩展）。

## 四、用户与角色
- 管理员（唯一角色，拥有全部当前可用操作能力）。

## 五、核心用例（自然语言）
1. 上传文件：管理员选择一个 CSV（≤1MB）上传，系统创建任务并返回初始规则建议与前 20 行预览。
2. 多轮规则修正：管理员通过输入自然语言指令（例如“邮箱列统一小写并去除空格”“部门字段如果是‘研发部’转换为‘R&D’”），系统更新规则草稿并刷新预览。可多轮迭代。
3. 确认规则：管理员确认后执行完整标准化，生成结果文件与错误行文件（如存在）。
4. 下载：管理员下载最终标准化结果；如有错误行，可额外下载错误行文件。
5. 登录与会话：管理员先登录获取访问权限；会话超过设定过期时间需重新登录。
6. 并行任务：管理员可在一个浏览器会话中开启多个任务（各自独立的上传 → 交互 → 确认流程）。

## 六、交互流程（阶段性描述）
1. 登录：输入初始管理员凭证 → 获得会话令牌。
2. 上传：提交 CSV → 系统解析列信息、样本统计 → 返回任务标识、初始规则建议与预览。
3. 对话迭代：管理员输入指令；系统生成新的规则解释与更新预览（覆盖前一版草稿）。
4. 重复第 3 步，直至管理员认同规则效果。
5. 确认：管理员触发“确认标准化”，系统对全量数据执行标准化，记录结果统计与错误行。
6. 下载：管理员获取标准化结果与错误行文件。
7. 任务锁定：已确认的任务不再允许进一步对话修改（如需修改，需新建任务）。

## 七、验收标准（Acceptance Criteria）
1. 上传一个合法 CSV（UTF-8 或可识别编码）后，系统返回：task id、初始规则建议说明文本、预览（前 20 行）、基础列统计（列数、行数）。
2. 上传非 CSV 或扩展名不符文件时，返回错误（例如：错误码/字段包含“INVALID_FILE_TYPE”）。
3. 上传超过 1MB 的文件被拒绝并返回明确错误（例如：错误码包含“FILE_TOO_LARGE”）。
4. 在同一个任务中，发送多轮自然语言指令（≥5 轮）后，每轮均返回新的规则描述与更新预览，无历史意图丢失。
5. 预览始终只显示标准化后的前 20 行，且列顺序与当前规则草稿描述一致。
6. 在任务未确认前，尝试下载结果文件会返回错误（例如：错误码“RESULT_NOT_READY”）。
7. 确认后任务状态更新为“已应用”（或等价标识），再次尝试发送修改指令会被拒绝并给出提示。
8. 确认执行成功后可下载：标准化结果文件（文件名以`normalized_<原文件名>_<时间戳>.csv` 命名）。
9. 若存在错误行，可下载错误行文件（命名格式：`errors_<task_id>.csv`），其中包含原始行号、失败原因文字。
10. 错误行文件不存在时访问其下载接口返回 404 或等价错误码。
11. 登录后所有受保护接口在会话 3 小时内有效；过期访问返回 401（不暴露内部堆栈）。
12. 使用错误凭证登录被拒绝并返回通用“认证失败”提示，不泄露是否用户名存在。
13. 并行创建两个任务（在同一登录会话下）不会互相覆盖数据或预览。
14. 已生成的结果文件与错误行文件可在下载后保留（不会立即删除）。
15. 服务重启后，已创建但未确认或已确认的任务仍可被查询（最少包括：状态、规则草稿或最终结果可继续下载）。
16. 当标准化过程中遇到无法转换的记录，系统不会导致整个任务失败，而是计入错误行并继续处理其它记录。
17. 所有错误返回结构统一（包含顶层错误码与可读消息）。
18. 假设一个空表头或仅表头无数据的 CSV，系统返回“可处理”并生成一个空结果文件（无数据但结构有效）。
19. 任务确认前后日志需记录：任务标识、原文件名、初始行数、成功行数、错误行数。
20. 同一浏览器多标签操作不同任务不会串行返回错误（上下文隔离）。

## 八、边界场景
- 空文件 / 仅表头：允许创建任务，确认后输出结构化空文件。
- 列名重复：需在预览中提示（业务上仍可继续，但列冲突显示警告）。
- 行数据列数不一致：将超出或缺失的列标记为错误行（或跳过）——具体策略在设计阶段细化。
- 编码异常（非 UTF-8）无法解码：返回统一错误提示“文件编码不支持”。
- 大写/小写混合或包含中文列名：允许并在规则建议中正常显示。
- 多轮对话中用户输入与标准化无关指令（如“讲个笑话”）：系统返回提示“超出标准化范围”。
- 任务已确认后再尝试“确认”操作：返回错误提示“已锁定”。
- 并发发起两次“确认”请求：只有第一次成功，第二次返回“已处理或锁定”。
- 上传同名文件多次（不同任务）：各任务独立，不复用之前的结果。
- 文件大小接近 1MB 边界：允许 ≤1MB（含），>1MB 拒绝。

## 九、约束与非功能需求
- 执行模式：全部同步（未引入队列与异步调度）。
- 性能：1MB 文件（假设若干千行级别）单次标准化在可接受时间内完成（未给硬性数值，本阶段不作性能优化考核）。
- 预览上限：固定 20 行；不支持浏览分页。
- 安全：
  - 仅管理员用户；最小登录机制；令牌有效期 3 小时。
  - 不在响应中返回内部堆栈细节。
- 可扩展性：任务、规则、会话的域概念须清晰，为异步化、多角色、GitHub App 集成留接口空间（具体实现不在本阶段约束）。
- 持久化：需保证任务与结果在服务重启后可继续访问；具体介质（文件/嵌入式数据库等）不在本需求中锁定。
- 兼容性：继续允许原 CLI 脚本在本阶段通过 import 使用标准化逻辑（无需强制 HTTP 调用）。
- 部署：支持容器化（Docker）与本地运行；需求文档不规定镜像结构细节。
- 日志：必须记录关键业务事件（上传、对话、确认、下载），格式不强制。

## 十、风险 / 问题
- 多轮对话上下文可能膨胀，需未来在设计层面做“摘要/截断”策略（本阶段仅提出风险，不执行）。
- 同步执行在更大文件规模会带来超时风险（超出 1MB 的未来扩展）。
- 规则含义与用户期望可能不一致，需前端明确提示“预览仅供参考，确认后不可更改”。
- 无审计日志细化可能影响后续合规（延迟到后续阶段）。
- 错误行解释粒度不足会影响调试效率（后续可增强错误分类与建议修复）。

## 十一、数据 / 兼容影响
- 新增“任务”与“规则草稿”的域概念；不影响现有 CLI 调用方式。
- 未来引入数据库时需迁移：现有任务与结果文件 → 持久存储（建立映射表）。
- 结果文件命名规范需在后续阶段保持稳定以便脚本自动处理（当前约定：`normalized_<原文件名>_<时间戳>.csv`）。

## 十二、测试提示（可选）
建议的测试分层：
- 单元：规则预览生成、错误行统计逻辑、权限校验。
- 集成：上传→多轮对话→确认→下载完整链路。
- 边界：空文件、1MB 边界文件、重复列名、错误文件类型。
- 会话：令牌过期模拟（可强制缩短过期时间测试）。
- 并发：两个任务并行操作互不污染。

## 十四、附录（术语）
- 任务（Task）：一次从“上传原始文件”开始，到“确认并生成最终结果”结束的闭环实体。
- 规则草稿（Rule Draft）：可迭代修改的标准化意图集合，用于驱动预览生成。
- 预览（Preview）：应用当前规则草稿于部分（前 20 行）数据形成的示例结果。
- 错误行（Error Rows）：在确认执行阶段无法成功标准化的行集合（不阻断整体产出）。
