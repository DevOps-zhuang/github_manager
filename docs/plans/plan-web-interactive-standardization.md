## 摘要
将现有“数据标准化（含 AI 交互式规则修正）”能力从 CLI 内部调用重构为 Web 形态：后端使用 Python Flask 提供同步 API；前端使用 React 提供最小界面（登录 / 上传 / 多轮对话 / 预览 / 确认 / 下载）。暂不处理邀请执行、异步、GitHub App、多组织；CLI 集成可延后。无需引入数据库，任务与规则落盘文件持久化即可。最终交付可 Docker 运行的一体化服务（前后端可同域或反向代理）。

## 范围
### 范围内
- Flask 后端骨架（认证 / 上传 / 任务管理 / 对话接口 / 预览 / 确认 / 下载 / 健康检查）。
- 规则草稿/会话的最小持久化（文件方式）。
- React 前端最小界面：登录、任务创建、对话面板、规则草稿展示（文本）、预览表格（前 20 行）、统计与下载按钮。
- 错误行文件生成与下载。
- 基础日志（任务创建 / 对话 / 确认 / 下载）。
- 容器化（Dockerfile + 简单启动脚本）。

### 不包含
- 邀请执行 API / GitHub 组织操作。
- 异步任务队列、进度轮询、任务取消。
- 多角色 / 多组织 / GitHub App / Webhook。
- 审计日志结构化存储、操作回放。
- 规则版本回滚 / 导出 / 导入。
- 国际化 / UI 主题化。
- 性能与压力专项优化。

## 设计要点
### 数据 / 模型（概念）
- Task：`id` / 原文件元数据 / 状态(pending|interactive|applied) / 规则草稿（文本或结构化简化内部对象）/ 会话摘要 / 预览片段 / 结果路径 / 错误路径。
- Conversation：按任务维护的轮次列表（role, content, timestamp）。
- Preview：基于当前规则草稿实时生成（限制 20 行）。

### 服务划分（逻辑层次）
1. API 层：Flask 蓝图（auth / normalize / download / health）。
2. 应用服务：NormalizationService（封装规则更新与预览计算）、TaskRepository（文件读写）、ConversationManager。
3. 领域执行：NormalizationExecutor（加载文件 → 应用规则 → 输出结果 / 错误）。
4. AI 适配：RuleSuggestionEngine（包装现有 AI 规则生成逻辑；若当前依赖内部模块则做薄封装）。

### 存储
- 目录结构（示例，可在实现阶段微调）：
  - `runtime/tasks/<task_id>.json`
  - `runtime/uploads/<task_id>_<orig>.csv`
  - `runtime/results/normalized_<orig>_<ts>.csv`
  - `runtime/results/errors_<task_id>.csv`
- 文件写入使用原子替换（先写临时文件再 rename）。

### 安全 / 认证
- 初始管理员用户名/密码来源 `.env`（如：`ADMIN_USERNAME` / `ADMIN_PASSWORD`）。
- 登录成功创建短期会话 token（JWT 或 HMAC 签名；过期：3h）。
- 所有非公开路由需校验 token。

### 性能 / 分页
- 仅预览 20 行，无分页。
- 全量标准化一次性内存操作（≤1MB 假设可接受）。

### 回滚策略
- 出现严重缺陷：代码回滚；任务文件兼容保留。

## 测试策略
- 单元测试：
  - 任务生成（文件校验 / 大小限制）。
  - 规则草稿更新（多轮覆盖上一轮）。
  - 预览函数：给定模拟规则 + 输入行 → 输出列一致。
  - 错误行抽取（格式错误 / 映射缺失）。
- 集成测试：
  - 上传→对话 3 轮→确认→下载（结果非空）。
  - 两任务并行执行，互不影响。
- 边界：空文件、仅表头、重复列、1MB 边界、非 CSV。
- 恶意：伪造 token / 过期 token / 重复确认。
- 持久化：重启后任务可查（模拟加载）。

## 风险与应对
| 风险 | 说明 | 应对 |
| ---- | ---- | ---- |
| AI 规则易偏差 | 多轮后规则仍不符合期望 | 前端提示“需人工核对预览” + 可新建任务重试 |
| 预览与最终结果不一致 | 预览仅 20 行可能遗漏边缘数据 | 在确认前突出提示“最终结果可能包含未在预览展示的异常” |
| 文件落盘一致性 | 并发写入任务 JSON 可能覆盖 | 加文件锁 / 原子写临时文件后 rename |
| 性能退化 | 未来文件 >1MB 需求上升 | 文档注明同步模式限制，计划 Phase2 异步化 |
| 安全凭证泄露 | 初始密码未修改 | 首次登录提示强制修改（可放入 Phase1.5） |
| 对话上下文膨胀 | token 过大影响响应 | 暂限制轮次（如保留最近 8 轮 + 摘要占位） |

## 度量（成功标准）
- 需求验收标准 20 条全部通过。
- 上传≤1MB 文件端到端（上传→确认→下载）流程 ≤ 10 秒（参考目标）。
- 多轮对话（≥5）无上下文丢失。
- 重启恢复测试通过（任务与结果仍可访问）。

## 发布
- 环境：本地 / 内网服务器 / Docker 容器。
- 初次部署步骤：
  1. 准备 `.env`（管理员用户名/密码）。
  2. 构建镜像并启动。
  3. 访问登录 → 上传测试 CSV → 多轮对话 → 确认 → 下载手工验收。
- 验证清单：
  - 健康检查 200。
  - 未登录访问受保护接口 401。
  - 上传合法 CSV 成功创建任务。
  - 多轮对话预览更新。
  - 确认后下载结果与错误行文件。
  - 重启后任务仍可查询。

## 后续可能优化（Phase 2+ 候选）
- 异步执行 + 任务进度轮询 / WebSocket。
- 结构化规则格式标准化（带 schemaVersion）。
- 规则版本快照 / 回滚。
- 多组织 / GitHub App / Webhook 事件触发自动规范化。
- 审计日志（操作 / IP / 历史规则 diff）。
- 增量导入（对比旧文件生成差异集）。
- 大文件分块/流式处理与并行化。
- RBAC（多用户+只读）。
- 预览差异高亮（原值 vs 新值）。
